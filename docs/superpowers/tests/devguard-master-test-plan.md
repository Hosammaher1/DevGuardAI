Roadmap inclusion is not availability. Detecting a framework does not imply executable support. Scan and Fix capabilities are separate; a supported Scan profile can still have unsupported Fix verification. PLANNED/SUPPORTED/PARTIAL/BLOCKED/UNSUPPORTED and version limits must remain explicit. R1 shared invariants repeat for each later release's available capabilities; future native implementation is not an R1 release prerequisite.

## 3. Case schema, actors and future fixtures

Each row includes stable ID; PD and relevant SG references; priority; release/platform; actor/permissions; Given/When/Then (expected observable result); security/quota side effect; test type and proposed automation target; unresolved decision marker; and initial status. IDs retain their original meaning and are not renumbered. The audit table in §5 accounts for every original case.

Priorities: P0 for authorization, tenant isolation, secrets, escape, approval bypass and billing/release integrity; P1 for functional/integration/evidence/recovery correctness; P2 for supplementary usability. Actor permissions always come from current trusted membership/policy, never a submitted tenant ID or an AI recommendation. A role-specific oracle with ND01 cannot be accepted until its matrix is approved.

Fixtures to specify and later build, not created here:

- **F-TENANT / F-RBAC:** independent A/B personal/Team workspaces, private repositories/artifacts/ledgers and Owner/Admin/Member/Viewer accounts; approved action matrix includes API, queues, membership, artifacts, approvals and billing.
- **F-POLICY:** versioned scope, budget, capability and financial policies. Fixtures using unresolved policy values carry NEEDS_DECISION; no silent defaults.
- **F-GITHUB:** dedicated OAuth/App integration fixtures, stable GitHub IDs, selected private repositories, branch/SHA/diff identities, signed/replayed events and controlled provider faults.
- **F-RUNNER:** explicitly authorized disposable external sandbox; observable host/tenant isolation, network, filesystem, CPU/RAM/disk/process/time/token/browser/concurrency bounds; no attack is run on trusted app hosts.
- **F-APP:** disposable React/Vite/vanilla, API and composite fixtures with known success/fail/denial/timeout outcomes; production targets allow only authorized non-destructive tests.
- **F-BROKER:** synthetic secret sentinels and trusted login broker/Playwright process; secrets never enter AI or arbitrary repository-command context.
- **F-EVIDENCE:** immutable job/SHA/platform identities; sanitized screenshots/logs/patches; controlled clock, expiry, corruption and cross-tenant retrieval attempts.
- **F-AI:** versioned deterministic and rubric corpora for agent/chatbot/RAG, grounded/unfounded answers, correct/incorrect tool calls, injection and provider faults; brokered/mock side effects only.
- **F-NATIVE:** independent vetted Android/iOS/desktop profiles, clean devices/simulators/OS sessions, permission/host-probe/failure/cleanup fixtures.
- **F-FAULT:** controlled queue/database/cache/storage/provider faults, crash points, event order and concurrent barriers; real persistence required for financial/authorization evidence.
- **F-RELEASE:** revision/policy/profile-bound evidence index, agreed threat model, incident/pilot/Go-No-Go records and actual cost data.

Mandatory parameter sets at future execution: tenant A/B and revoked membership; manual/automatic triggers; signature valid/invalid/replayed; supported/unvetted versions; normal/at/beyond configured budgets; success/failure/cancel/crash/timeout; duplicate/reordered/concurrent events; scan versus fix; paid period/renewal boundaries. Network attacks include private IPv4/IPv6, loopback, link-local/cloud metadata, alternate encodings, redirects and DNS rebinding checked at connection time, plus positive phase-allowlist traffic. Instantiate each approved platform profile separately and preserve case ID plus fixture parameter identity in evidence.

A runtime expected BLOCKED/UNSUPPORTED result is an assertion in a future test, not permission to mark this written case executed. Proposed targets are destinations for automation, not existing tests or commands. All ND markers refer to §8. No mock-only check certifies actual isolation, ledger concurrency, provider permission or recovery behavior.
